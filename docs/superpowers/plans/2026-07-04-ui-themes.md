# UI Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a polished multi-theme clinical dashboard UI to the existing Tauri React client.

**Architecture:** Extend the existing settings domain with a `theme` field and drive all visual surfaces through CSS variables. Keep components focused: App owns shell state and theme application, SettingsPanel owns setting controls, WaveformCanvas owns canvas drawing using theme-aware CSS values.

**Tech Stack:** React 19, TypeScript, Vite, Vitest, CSS variables, Canvas 2D, lucide-react.

## Global Constraints

- Always answer user-facing communication in Simplified Chinese.
- Do not create git branches, commits, pushes, or resets unless explicitly requested.
- Do not change BLE, protocol parsing, CSV recording, or Rust backend behavior.
- Keep first screen as the usable dashboard.
- Avoid decorative orbs and marketing-style hero layouts.
- Use semantic CSS variables for theme colors.
- Preserve EEG mode layout and all existing settings.

---

## File Structure

- `src/domain/settings.ts`: add theme type, options, default, and merge behavior.
- `src/domain/settings.test.ts`: add tests for theme defaults and persistence.
- `src/App.tsx`: apply theme attribute and add top-bar theme selector.
- `src/components/SettingsPanel.tsx`: add theme selector and improve setting group semantics.
- `src/components/WaveformCanvas.tsx`: read theme CSS variables for canvas background, grid, text, and legend.
- `src/components/BandShareChart.tsx`: add richer chart labels without changing data behavior.
- `src/components/EegModeView.tsx`: use theme-aware raw waveform color.
- `src/styles.css`: replace hardcoded surfaces with theme tokens and refine dashboard layout.
