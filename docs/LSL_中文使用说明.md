# iFET 头戴上位机 LSL 中文使用说明

## 1. LSL 是什么

LSL（Lab Streaming Layer，实验室数据流层）是一套面向科研实验的实时数据交换与时间同步协议。采集软件创建 **Outlet（输出端）** 发布 EEG、PPG、运动或事件流；LabRecorder、Python、MATLAB 等软件创建 **Inlet（输入端）** 发现并订阅这些流。

LSL 适合把头戴 EEG 与 PSG、眼动、刺激程序或行为任务放在同一时间轴上。LabRecorder 可以把多个 LSL 流统一保存为 XDF 文件，后续再进行时钟偏移校正和事件对齐。

## 2. 本版上位机的输出

开启“后台设置 → LSL → 启用 LSL 实时输出”后，上位机发布以下 4 条流：

| 流名后缀 | 类型 | 通道 | 数据格式 | 内容 |
| --- | --- | ---: | --- | --- |
| `_EEG` | EEG | 4 | int32 | EEG1–EEG4，有符号 24 位原始 ADC 计数 |
| `_AUX` | AUX | 9 | int32 | IR/Red/Green 两组 PPG 与 AccX/Y/Z |
| `_Quality` | Quality | 3 | int32 | Valid、DeviceSeq、DeviceFlag |
| `_Markers` | Markers | 1 | string | 手动标记和 PSG 对齐事件，JSON 字符串 |

例如流名称前缀为 `iFET-TD10` 时，EEG 流名为 `iFET-TD10_EEG`。

LSL 输出与 BLE 采集、本地 CSV 记录相互独立。LSL 接收端卡顿时，上位机不会阻塞 BLE 或写盘；设置页中的“LSL 丢弃批次”可用于检查 LSL 输出队列是否过载。

## 3. 使用方法

1. 连接 TD 头戴设备并确认上位机已有实时信号。
2. 打开“后台设置 → LSL”。
3. 设置流名称前缀和来源 ID。同一局域网内每台设备必须使用唯一来源 ID。
4. 勾选“启用 LSL 实时输出”。状态应变为“LSL 已发布，等待接收端”。
5. 打开 LabRecorder 或自己的 LSL Inlet，刷新流列表并选择需要的流。
6. 接收成功后，上位机状态变为“LSL 接收端已连接”。
7. 可点击“发送 LSL 测试标记”，确认 `_Markers` 流收到事件。

## 4. 时间同步和记录注意事项

- LSL 时间戳使用 liblsl 的单调时钟；跨电脑偏移由接收端的 LSL 时间校正机制估计。
- LabRecorder 保存为 XDF 时会同时保存时钟偏移信息，导入工具可在离线分析中校正时间轴。
- 上位机发布的是设备协议解析后的**原始计数**，不是界面滤波波形。`Valid=0` 的样本仍会保留，以便分析丢包和协议质量。
- `_Markers` 中同时保存标记名称、备注、参与者编号、样本计数、设备 Flag、算法动作和 UTC 墙钟时间。
- 设备没有独立的高精度硬件绝对时钟，因此 LSL 能校正电脑之间的网络时钟偏移，但不能消除 BLE 到达抖动或重建设备内部真实采样时刻。与 PSG 做严格验证时，仍建议使用“10 秒连续眨眼”等生理标记进行二次对齐。

## 5. 网络排查

- 两台电脑应位于同一局域网，且网络不能隔离客户端或屏蔽组播发现。
- Windows 首次运行时，应允许应用访问“专用网络”。
- 每个同时运行的头戴上位机应使用不同的来源 ID。
- 能发现流但收不到数据时，先确认 BLE 已连接且上位机样本计数持续增加。
- 上位机显示“LSL 丢弃批次”增长时，优先检查接收端性能、网络质量或减少不需要订阅的流。

## 6. 版本说明

本版内置的 liblsl 为静态链接，无需用户另外安装 DLL 或 dylib。LSL 协议版本为 1.10，能够与常用 LabRecorder、pylsl 和 MATLAB LSL 接口互操作。
