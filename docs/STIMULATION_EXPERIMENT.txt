iFET EEG Client Stimulus 0.3.0 — 声音刺激实验版
日期：2026-10-09

一、独立版本与适用范围
本版基于此 Mac 上当前 0.2.29 源码制作，应用名和 Bundle ID 独立：
iFET EEG Client Stimulus 0.3.0
com.ifet.eeg-client.stimulus-v030
不覆盖原来的 0.2.27/0.2.28/0.2.29。实验采用数据采集模式，不运行助眠音乐、
实时基线、睡眠分期或眨眼控制。原有功能代码保留，但不能与刺激实验同时启动。
仅用于研究和工程验证，不作为临床诊疗设备；音量百分比不是 dB SPL。

二、与所给 MATLAB 程序的对应关系
1. 默认每组 5 次、共 3 组，提示 1 秒、间隔 2 秒、组间手动继续。
2. 原程序的 Don chirp 为 CochleaChirp(5,44100,80,[20,20000],'Don')。
   当前只收到主程序，未收到 CochleaChirp.m，因此没有假装重建该波形。
   请在原 MATLAB 环境运行随附 scripts/export_original_don_chirp.m，生成 WAV。
   WAV 的内容和采样率不隐式改变；播放时乘以界面增益，默认 10%，最大 80%。
   默认增益与原程序 100% 不同，这是有意保守设置，正式实验请另行声压校准。
   WAV 若含前后静音，标记对应文件 PCM 起止边界，不自动寻找第一声学脉冲。
3. 内置 1000 Hz 测试音仅供连通性测试，不是 Don chirp，也不是 80 Hz ASSR 刺激。
4. 串口：115200、8N1，无流控；打开后等待 2.5 秒，发 ASCII P，1 秒内期待 A。
   握手不成功就停止，不发 T、不开始声音。各次开始时发送 ASCII T（0x54）。
   结束时可选再发一个 T，默认开启。与原程序相比新增“结束 T”。
   T 是相同未编码脉冲；组号、次数、起止类型保存在软件记录，不在 TTL 中编码。
5. 未收到 Arduino_TTL_Trigger.ino，不猜测 TTL 引脚、电压或脉宽；使用原已验证固件。
   接线、电平兼容、设备电气隔离和临床设备触发接口必须由实验人员确认。
6. 原程序用 PsychPortAudio 返回的开始时间后再发 T；本版使用原生音频回调的
   预测 DAC 时间并按该时间派发 T，不能视为两套硬件时序已经等价。
7. “+”及界面颜色是操作提示，未经屏幕刷新同步测量，不作为视觉刺激时标。

三、使用步骤
1. 启动独立实验版，点击“进入实验采集模式”。建议先关闭其他播放声音的软件。
2. 连接 TD 头带，确认四通道有真实有效数据，选择采样率并等接收稳定。
3. 在设置中选择保存目录，填写受试者编号，点击记录。自动标记不允许用于演示数据。
4. 导入原刺激 WAV，选择有线音频输出设备。不要把蓝牙耳机作为精确时序实验输出。
5. 如需外部 EEG/PSG 同步，勾选 Arduino TTL，选择对应串口，决定是否结束也发 T。
6. 设置组次/提示/间隔，先以低音量和短实验确认连通性，再点击“开始刺激并打标”。
7. 声音开始、结束、提示、组结束和完成自动留痕。运行后参数自动收起；可随时展开。
8. “停止 / Esc”中止，若正播放则补一个 interrupted 的声音结束事件；等待状态结束
   后再停止 EEG 记录。关闭窗口第一次会请求停止并保留窗口，以便写完末尾事件。
9. EEG 超过 2.5 秒无有效数据、音频驱动故障、事件队列溢出、串口写失败都会中止。
   硬件故障无法确认准确结束时间时，写 forced_abort_uncertain，不伪造精确结束。
10. 刺激期间不能更换采样率、发送设备配置命令、另开记录或提前关闭记录。

四、记录文件及对齐方法
• ppg_eeg_log_*.csv：原有原始 EEG/PPG/运动/有效性记录，未插入伪样本、未改变滤波。
• 同名 *_markers.csv：自动声音起止和其他事件；time 是捕获的音频时钟预测输出时间。
• stimulus_<runId>.csv：每个事件的回调时间、后台处理时间、预期输出时间、实际派发
  时间、处理延迟、串口写耗时/错误、音频缓冲大小和是否中止。
• stimulus_<runId>.json：配置、WAV SHA-256、采样率、设备、文件路径及时间戳语义。

对齐必须使用 markers.csv 的 time 列与 EEG 的 time 列。sampleCount 只是当时已写入的
行数，不是声音发生时的精确 EEG 索引，因为 BLE 数据会分包延迟到达。
algorithmAction：sound_on / sound_off / cue / block_end / complete / aborted /
forced_abort_uncertain。开始和结束通过 runId、block、trial 配对。
这是独立标记旁文件，不是修改头带固件的 flag 位，也不是 Neuracle 文件内部打标。
给外部 Neuracle/PSG 的硬件打标仍依赖接好的 Arduino TTL 线路。
本版自动刺激事件写本地 CSV；现有 EEG LSL 流和人工标记功能保留，未新增刺激事件 LSL 推送。

五、如何理解延迟
标记 time 是驱动预测 DAC 输出时刻，提前捕获，不是网页按钮响应时间，也不是磁盘
完成时间。声卡等待时间是预测的一部分，并非简单再加到已保存的事件时间上。
dispatchLatenessMs 表示软件派发比预测 DAC 时刻晚多少，serialWriteMs 仅为主机串口
调用耗时。二者均不能证明实际 Arduino 引脚或耳边声音的延迟。
115200 baud、8N1 发 1 字节的线路理论时间约 0.087 ms；USB 帧、固件处理、TTL 脉宽、
声卡内部延迟及扬声器声学传播均另计，尚未实测。
EEG 使用主机到达时间锚定的逻辑采样时钟，没有与声卡共享硬件时钟，BLE 运输偏差未测。
125/250/500/1000 Hz 的最近采样点量化上限分别为约 ±4/±2/±1/±0.5 ms，
这仅是采样量化误差，不是整个系统总误差上限。
Mac 实测见另附时序报告。Windows 必须在目标机器用“静音时序自测”另测，不套用 Mac 数字。
静音自测不会发送串口命令、不改 EEG、不播放有声刺激；它不是硬件回环校准。

六、正式实验前必做的硬件验证
用同一个采集设备同时记录音频电信号/声学传感器和 Arduino TTL。
若做声学实验，麦克风靠近实际耳机耦合位置；仅线缆回环不能测扬声器/耳机声学延迟。
分别在 125/250/500/1000 Hz、正常后台负载、目标声卡与目标 Windows/Mac 上至少测 100 次。
报告开始/结束的中位数、P95、最大值、标准差；检查漏触发、乱序和退出时额外脉冲。
以共有回环/TTL事件校正系统偏移，不要用本机软件日志直接声称毫秒级神经反应时准确度。
原 Don chirp 用于 80 Hz 反应分析时，125 Hz EEG 的奈奎斯特频率仅 62.5 Hz，不能直接
可靠表示 80 Hz 基频；正式采样率须结合设备前端带宽和研究目的另行确认。

七、已验证与未验证
已做：前端类型检查与自动测试，Rust 协议/音频采样级时序/中止/记录目标保护测试，
Mac 内置声卡静音回调和写盘/派发计时，独立应用构建与界面检查。
未做：原 CochleaChirp 波形复现、原 Arduino 固件实机、真实 TTL 引脚、声学回环、
Neuracle 接线、真实头带与刺激同时记录、Windows 硬件时序。
上述未验证项不能被“应用构建成功”代替。
