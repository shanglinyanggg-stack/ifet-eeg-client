# 头戴设备四通道配对眨眼控制算法交接（v1.0.13）

本目录可直接发给 App 工程师及其 Codex。正式 App 应复现这里的状态机、校准与日志语义，不要只复制若干固定阈值。

## 1. 本版结论

- Alpha 音量和睡眠模型仍只使用 EEG1、EEG2；不要因本次改动重训或替换睡眠模型。
- 眨眼使用 EEG1–EEG4，但不是任意四通道投票。固定计算两对：`EEG1+EEG2`、`EEG3+EEG4`。
- 每次佩戴都要先做 3 秒安静背景和 10 秒连续自然眨眼。每对至少获得 5 个同步校准峰才允许在线参与。
- 在线候选由两个通道同步响应确认，不允许单通道降级；两对都可用时选择当时融合强度更高的一对。
- 个体眨眼中心与尺度在校准后冻结。实时背景只做健康监测；漂移连续超限时暂停并要求重测，不能自动缩小尺度。
- BLE 无效样本后的保护窗是 0.20 秒且严格因果。后面才出现的丢包不能追溯删除此前真实峰。
- 仅连续无效达到 0.35 秒才清空整组三/五次手势。短丢包可保留此前有效眨眼。
- 五次优先于三次。三次需等待末次眨眼后至少 2.05 秒；第五次到达前不得先下发三次动作。

## 2. 输入与必须提供的 App 功能

算法输入：

- EEG：`float[4][N]`，顺序固定 EEG1–EEG4，100 Hz 因果流。
- `valid[N]`：BLE 传输有效性和数值有限性合并后的布尔序列。
- IMU：至少三轴加速度，同样的时间轴；没有 IMU 时可运行，但必须在日志中标记运动门控不可用。
- 过滤器状态必须跨 BLE chunk 保存，不允许逐包重新初始化。

App 必须提供：

1. “测量 3 秒安静 + 10 秒连续眨眼”按钮、进度和成功/失败原因。
2. 显示启用的校准配对，例如 `EEG1+EEG2 / EEG3+EEG4`。
3. 基线 stale 时暂停眨眼控制并提示检查佩戴、重新校准。
4. “仅眨眼验证并记录”模式：不要求音乐或 Alpha 基线，禁用音频动作，但完整保存原始 EEG、IMU、valid、校准画像和算法事件。
5. 独立的 0/3/5 真值按钮，每组固定 10 秒；上一组未结束时拒绝新标记。
6. 测试标记开始和产生结果时清空待定候选、部分手势和冷却状态，避免组间污染。
7. 日志至少包含：marker、expected count、detected count、success、timeout、所有 `BLINK/BLINK_3/BLINK_5`、音量动作前后值和算法版本。

## 3. 因果预处理

眨眼支路使用三阶 Butterworth 0.5–8 Hz 带通，SOS 实现。对每个通道单独保存滤波器状态。

无效输入样本只用上一个有效的原始 EEG 样本补齐，以维持滤波器状态；绝不能把已经滤波的值写回原始输入。无效样本仍保持 `valid=false`，补齐不代表可用于判定。

## 4. 个体校准

### 4.1 3 秒安静背景

用户保持睁眼、头部和下颌不动，不眨眼。对四通道分别计算：

```text
center_c = median(x_c)
scale_c  = max(1.4826 * MAD(x_c), (Q90-Q10)/2.5631, minimum_scale)
z_c(t)   = abs((x_c(t)-center_c)/scale_c)
```

校准成功后 `center_c` 和 `scale_c` 冻结。重新佩戴、移动电极、接触/阻抗明显变化或长时间断连后要显式重测。

### 4.2 10 秒连续自然眨眼

用户保持头部和下颌不动，每 0.5–1.0 秒自然眨眼一次。分别对两个固定配对计算：

```text
primary_p(t)   = max(z_a(t), z_b(t))
secondary_p(t) = min(z_a(t), z_b(t))
fused_p(t)     = sqrt(primary_p(t) * secondary_p(t))
```

在所有配对融合包络上找峰：高度至少 2.0z、prominence 至少 0.8z、距离至少 0.32 秒、宽度 0.025–0.80 秒。一个配对只有在至少 5 个候选峰上同时满足 `secondary>=2.0z` 和 `fused>=2.0z`，才加入在线 enabled pairs。

总体校准还需满足：

- 配对有效峰不少于 5；
- 配对有效峰/全部候选峰不低于 65%；
- 有效峰融合强度中位数不低于 3z。

运行阈值：

```text
如果 EEG3+EEG4 已启用：T = clip(Q25(valid_fused_peak_strength) * 0.30, 2.5, 3.25)
如果只有 EEG1+EEG2：T = clip(Q25(valid_fused_peak_strength) * 0.45, 2.5, 6.0)
secondary_floor = 0.60 * T
```

条件分支用于兼容已验证的 EEG1+EEG2 单配对：在该配对上过低阈值会把强眨眼的滤波尾部计成额外峰；当前头戴的 EEG3+EEG4 响应明显更强，因此启用该配对时需要较低上限保留第四、第五次自然衰减的眨眼。

同时保存中位峰宽、中位眨眼间隔、主要极性、配对一致率和校准 IMU 分布。极性仅作诊断，不要求两个通道同极性。

## 5. 在线单次眨眼判定

对每个 enabled pair 计算 `primary/secondary/fused`，选择当时 `fused` 最大的一对。只有同时满足下列条件才产生一个候选：

```text
winning_pair.secondary >= 0.60*T
winning_pair.fused >= T
fused envelope is a local maximum
distance from previous peak >= 0.32 s
valid at the peak
peak is at least 0.20 s after the last invalid sample
IMU motion gate passes
```

峰时刻必须由获胜配对融合包络决定，不能用最强单通道的峰时刻代替。任意单通道尖峰不得产生 `BLINK`。

## 6. 短缺包与节律补偿

旧算法把任意丢包前后 0.8 秒都删除，并立即清空整组，导致五次眨眼中的多次真实峰消失。本版规则：

- 只拒绝无效样本之后 0.20 秒内的候选；后续丢包不追溯删除此前峰。
- 连续无效少于 0.35 秒时保留已经确认的组内眨眼；达到 0.35 秒才清空整组。
- 可补偿最多一个被短丢包遮挡的眨眼，但必须同时满足：已有至少两个有效组内眨眼；无效样本位于前后两个确认峰之间；该间隔为校准中位间隔的 1.65–2.60 倍。
- 补偿时刻取相邻峰中点，补偿强度取相邻强度几何均值。没有 invalid 证据时绝不能只因间隔较长而补峰。

## 7. 三次/五次状态机

- 组窗口 7.0 秒。
- 最短间隔 `max(0.16, min(0.65*校准中位间隔, 0.50))`。
- 最长间隔 `max(1.40, min(2.25*校准中位间隔, 1.80))`。
- 组内间隔极差不超过 0.45 秒。
- 幅度比仅作宽范围伪迹保护：0.05–25.0，不能因后续眨眼自然变弱而删除。
- 达到五次立即输出 `BLINK_5`。
- 三次只在末次峰后 `max(2.05, 最长间隔+0.25)` 秒仍无第四/第五次时输出 `BLINK_3`。
- 若最终留下四个峰，且第四峰小于前三峰中位强度的 0.55，可将第四峰视为波形尾部并输出保留的三次；如果第五峰先到，仍必须输出五次。
- 动作后冷却 0.60 秒。

音量默认：三次 `-10%`，五次 `+10%`，裁剪到 `[0, 用户最高音量]`。若 Alpha 同时控制音量，保存眨眼 offset，并在裁剪后同步为真实 offset，不能积累看不见的边界债务。

## 8. 基线健康监测

默认 `adaptive_blink_baseline=false`。只在低运动、非高置信眨眼、有效背景中计算 90 秒历史中心和尺度；每 5 秒检查一次：尺度比允许 0.10–2.50，中心漂移不超过 2.5 个当前尺度。连续 3 次失败后置 stale、清空待定手势、暂停控制并要求重新测量。

闭眼、睡眠或普通自然眨眼不能用来实时改写睁眼安静基线；否则尺度可能逐渐缩小并放大噪声。

## 9. 当前证据与边界

带标签真机会话 `20260718_161609_fdae23df877c` 的 v1.0.13 回放：

- 无指令：1/1；
- 三次：2/4；
- 五次：7/7；
- 错误控制指令：0；
- 总计：10/12（83.3%）。

历史五个真机会话回归未产生新的三/五次错误动作，已确认的五次眨眼仍保留；单通道合成校准被拒绝，0/3/5 控制器序列通过。

限制：旧 v1.0.11 会话只保存 EEG1/EEG2 校准参数，本次回放的 EEG3/EEG4 中心和尺度由无指令段前 3 秒追溯估计。因此 7/7 五次是有价值的回放证据，但不是独立前瞻准确率。正式 Demo 门槛仍建议每类至少 20 组，三次/五次灵敏度均不低于 90%，3/5 错分率和无指令误触率均不高于 5%，并覆盖说话、咀嚼、抬眉、点头、触碰电极、翻身和不同佩戴。
